# CareerOS 大模型知识与选型指南

> 版本：V1.0｜更新时间：2026-08-01｜用途：产品选型、开发学习、面试说明

## 1. 先建立正确认识

“大模型”不是一个单一商品。开发 AI 产品时需要区分：

1. **模型**：真正进行推理的能力，例如 DeepSeek V4 Flash、Qwen、Gemini、GPT、Claude。
2. **API**：程序调用模型的接口。
3. **模型平台**：统一提供密钥、计费、日志和多个模型，例如阿里云百炼、Cloudflare Workers AI。
4. **工具**：数据库查询、创建任务、联网搜索等实际能力；模型只决定是否调用，代码负责执行。
5. **Agent**：模型在循环中观察、思考、调用工具、读取结果并继续行动的系统。
6. **RAG**：先从私人知识库检索资料，再让模型依据资料回答。
7. **Embedding**：把内容转为向量，负责语义检索，不负责写答案。
8. **OCR/视觉模型**：读取图片文字或理解图片。

因此，“接入一个 Agent 模型”可以统一很多文本任务，但不能自动拥有数据库、OCR、搜索和文件访问能力。

## 2. 模型按能力分类

| 类型 | 主要能力 | CareerOS 用途 |
|---|---|---|
| 通用文本模型 | 理解、总结、分类、生成 | 知识卡、JD、笔记、简历 |
| 推理模型 | 多步骤分析、规划、复杂判断 | 项目匹配、差距分析、Agent |
| 视觉语言模型 | 同时理解文字和图片 | JD 截图、知识照片、图片笔记 |
| Embedding 模型 | 把内容转成语义向量 | 知识搜索、相似 JD、项目召回 |
| Reranker 模型 | 对检索结果重新排序 | 提高知识库搜索准确率 |
| OCR 模型/服务 | 提取图片文字与位置 | 招聘软件截图、扫描资料 |
| 语音模型 | 语音识别或语音合成 | 语音随手记（升级版） |
| 图像生成模型 | 生成或编辑图片 | 当前不是 CareerOS 核心需求 |

另一个重要维度是规模：

- **Flash / Mini / Nano / Air / Lite**：便宜、快，适合大量简单任务。
- **Plus / Standard / Sonnet / Terra**：质量、速度和价格比较平衡。
- **Max / Pro / Opus / Sol**：复杂任务质量更好，但更慢、更贵。

这些名称不是统一标准，各家公司只是用类似方式表达产品档位。

## 3. 主流模型与平台地图

### 3.1 DeepSeek

特点：中文能力强、价格低、推理与工具调用能力突出、OpenAI/Anthropic 兼容接口较容易接入。

- V4 Flash：适合成本敏感、调用频繁的文本和 Agent 任务。
- V4 Pro：适合更复杂的推理、编程和高质量生成。
- 局限：当前 CareerOS 仍需单独解决图片理解；思考模式与工具调用要正确回传上下文。

适合 CareerOS：文本知识卡、JD、笔记任务提取、项目匹配、简历草稿。

### 3.2 阿里通义千问 Qwen / 百炼

特点：中文与多模态能力完整，模型档位多，国内账号、网络、人民币计费和控制台管理方便。

- Flash：大量、便宜、快速任务。
- Plus：通用主力。
- Max：复杂任务。
- VL/带 vision 标识的模型：图片、文档和视觉理解。
- 百炼不仅提供 Qwen，也可以统一调用部分 DeepSeek、Kimi、GLM 等模型，并提供工作流、知识库和工具。

适合 CareerOS：如果希望一个国内平台同时解决文本、视觉、工具和后续知识库，百炼是重要候选。

### 3.3 Google Gemini

特点：原生多模态、长上下文、文档/图片/音视频理解、内置 Google Search、File Search、代码执行等工具较完整。

- Flash 系列：低延迟、价格较低、多模态。
- Pro 系列：复杂推理和长上下文。
- Gemini Embedding：支持文本，当前产品线还提供多模态向量能力。

适合 CareerOS：JD 长图、知识照片、PDF 资料理解，以及未来需要多模态知识库时。

注意：免费层和付费层可能有不同的数据使用规则，正式产品应确认地区、账单和数据条款。

### 3.4 OpenAI GPT

特点：Responses API、结构化输出、工具、文件检索、视觉、音频、图像、Agent SDK 等生态完整，工程文档成熟。

- Nano/Luna 等低成本档：分类、提取、标签等高频任务。
- Mini/Terra 等平衡档：通用产品功能。
- 旗舰/Sol/Pro 档：复杂推理和高质量 Agent。
- 独立 Embedding、语音、图像与实时模型覆盖完整。

适合 CareerOS：需要成熟 Agent 工具链、严格结构化输出和国际化扩展时。

局限：对个人中文 MVP 来说，旗舰模型成本通常高于 DeepSeek；ChatGPT Plus 会员不包含 API 用量，API 单独计费。

### 3.5 Anthropic Claude

特点：长文理解、写作、代码、工具使用和复杂 Agent 表现突出；常见档位为 Haiku（快/便宜）、Sonnet（平衡）、Opus（高能力）。

适合 CareerOS：高质量简历写作、长项目资料理解、复杂 Agent 流程。

局限：对当前个人 MVP 来说可能不是最低成本方案，国内开发和支付便利性也需要单独验证。

### 3.6 智谱 GLM

特点：国内模型平台，中文、工具调用、Agent 与多模态产品线较完整，国内接入和人民币计费方便。

适合 CareerOS：希望国内服务、中文 Agent 和视觉能力时，可作为 Qwen/DeepSeek 的对照测试模型。

### 3.7 月之暗面 Kimi

特点：长上下文、文档理解、中文内容处理和 Agent 能力是主要方向。

适合 CareerOS：长 JD、项目材料、PDF 或大量知识资料处理。

### 3.8 字节豆包

特点：国内云平台、模型档位多、价格竞争力和并发能力较强，覆盖文本、视觉、向量、语音等服务。

适合 CareerOS：国内公开产品、低成本高频调用、多模态和语音扩展。

### 3.9 开源模型与 Cloudflare Workers AI

Llama、Mistral、Qwen、Gemma、DeepSeek 系列中的部分模型属于开放权重模型，可以由云平台托管或自行部署。

Cloudflare Workers AI 提供大量托管开源模型，优点是与 CareerOS 当前 Workers、D1、R2、AI Gateway、Vectorize 同一平台，密钥、网络和日志更简单；缺点是模型更新与下线较快，中文和复杂推理质量必须实测。

自行部署模型意味着自己承担 GPU、扩缩容、监控和升级。CareerOS 个人 MVP 不建议自行部署。

## 4. 不能只看排行榜

选型至少要看以下 12 个维度：

| 维度 | 要问的问题 |
|---|---|
| 任务质量 | 对你的真实 JD、笔记、知识卡结果是否好？ |
| 中文能力 | 是否理解中文招聘表达、缩写和语气？ |
| 结构化输出 | 能否稳定返回符合 JSON Schema 的结果？ |
| 工具调用 | 是否正确选择工具和生成合法参数？ |
| 视觉 | 能否识别长截图、小字、表格和多张图片？ |
| 上下文 | 一次能放入多少资料？长上下文是否真的有效？ |
| 延迟 | 用户需要等待多久？首字时间和总耗时如何？ |
| 价格 | 输入、输出、思考、缓存、工具是否分别收费？ |
| 稳定性 | 限流、超时和服务可用性怎么样？ |
| 数据隐私 | 是否用于训练、保存多久、数据在哪个地区？ |
| 接入难度 | SDK、兼容格式、文档和错误处理是否成熟？ |
| 可替换性 | 将来换模型需要改一个配置还是重写业务？ |

“上下文达到 1M”“跑分第一”“支持工具调用”都不能证明它最适合 CareerOS。公开跑分和真实中文业务数据是两件事。

## 5. 价格怎么理解

大多数文本模型按 Token 计费：

```text
总费用 = 输入 Token × 输入单价 + 输出 Token × 输出单价
```

还可能包括：

- 思考 Token：通常按输出收费。
- 缓存：重复的系统提示词或长资料可降低输入费用。
- 图片 Token：按图片尺寸或换算后的 Token 收费。
- 搜索/工具：可能按调用次数额外收费。
- Batch：不要求立即返回时通常更便宜。
- 免费额度：可能有期限、速率和数据使用条件。

评估价格不能只看“每百万输入 Token”。知识卡与 Agent 往往输出较长，而输出通常更贵；复杂 Agent 还会多轮调用。

CareerOS 应记录每次调用：`provider`、`model`、`feature`、输入/输出量、耗时、成功状态、估算费用和用户是否接受结果。

## 6. API 是怎么接入的

前端不能直接保存模型密钥，正确结构是：

```text
CareerOS 前端
  → CareerOS 后端 API
  → 模型适配层
  → DeepSeek / Qwen / Gemini / OpenAI 等供应商
  → JSON 校验
  → 用户确认
  → D1 / R2
```

接入一家模型通常需要：

1. 注册模型平台并开通 API。
2. 创建 API Key。
3. 把密钥配置到 Cloudflare 服务端环境变量。
4. 配置 `base_url`、`model` 和供应商参数。
5. 编写系统提示词与 JSON Schema。
6. 处理超时、限流、重试和错误码。
7. 校验输出，绝不直接执行模型生成的参数。
8. 记录用量和费用。
9. 用真实样本做评测后才上线。

OpenAI-compatible 只表示接口形状相似，不代表思考字段、图片格式、工具调用和错误行为完全相同。

## 7. CareerOS 每项功能需要什么能力

| 功能 | 必要模型能力 | 暂不需要 |
|---|---|---|
| 随手记标题/分类/标签 | 便宜文本模型、JSON | 强推理、Embedding |
| 笔记提取任务 | 文本模型、结构化输出 | 多轮 Agent（首版） |
| 确认后创建任务 | CareerOS 普通 API | 模型直接写数据库 |
| 技术知识卡 | 中文文本、较长输出、事实质量 | 视觉（纯文字入口） |
| JD 文字整理 | 中文文本、结构化输出 | OCR |
| JD 截图整理 | 视觉或 OCR + 文本模型 | Embedding |
| 项目匹配 | 文本推理 + 规则评分 | 初期不必向量化 |
| 大量知识语义搜索 | Embedding + 向量存储 + Reranker | 每次扫描全部数据 |
| 简历草稿 | 高质量文本模型 + 证据约束 | 模型自由编造 |
| 自动化工作流 | 工具调用 + 权限 + 确认机制 | 无限制自主执行 |

## 8. CareerOS 推荐的模型路由

### AI MVP

- 主文本模型：DeepSeek V4 Flash，负责知识、JD、笔记和任务候选。
- 默认使用非思考模式；项目匹配等复杂任务再开启思考。
- 图片暂不开放或先使用 Cloudflare 上的视觉模型做小规模验证。
- 搜索先用 SQL、标题、标签和关键词。

选择原因：当前主要是中文文本结构化；个人使用量小；V4 Flash 价格低、支持 JSON 和工具调用；现有代码已经有 OpenAI-compatible 适配层。

### 图片阶段

同时对比两条路线：

1. Qwen 视觉模型：国内中文图片、长截图和统一百炼平台。
2. Gemini Flash：多模态、长文档和工具生态。

用 CareerOS 自己的 30—50 张 JD/知识截图评测后选择，不能提前仅靠品牌决定。

### 知识库阶段

- Embedding 候选：Cloudflare 的 BGE-M3/Qwen Embedding，或 Gemini Embedding。
- 存储候选：Cloudflare Vectorize，继续与当前架构统一。
- 检索流程：向量召回 → Reranker 排序 → 文本模型回答并引用来源。

### 高质量降级/升级

建立三级路由：

```text
简单任务 → 低成本快速模型
复杂任务 → 主力推理模型
失败/用户点击深度分析 → 高质量备用模型
```

不建议一开始同时维护五家供应商；每多一家都会增加密钥、账单、字段差异、测试和故障处理成本。

## 9. 如何科学选型：建立 CareerOS Evals

准备一套不包含敏感信息的测试集：

- 20 条不同类型随手记。
- 20 份不同平台 JD。
- 20 个技术知识问题。
- 10 组 JD—项目匹配。
- 10 张清晰/模糊/长图截图。

为每个模型记录：

| 指标 | 计算方式 |
|---|---|
| 字段完整率 | 必填字段正确返回的比例 |
| JSON 成功率 | 无需修复即可解析的比例 |
| 事实准确率 | 与原文一致的结论比例 |
| 任务误报率 | 普通想法被错误转成任务的比例 |
| 证据覆盖率 | 结论能找到原文依据的比例 |
| 用户修改率 | 用户需要修改的字段比例 |
| 平均延迟 | 从请求到完整结果的时间 |
| 单次成本 | 输入、输出和工具的总费用 |

选型公式可以是：

```text
总分 = 质量 40% + 稳定性 20% + 成本 15% + 延迟 10%
     + 中文/视觉适配 10% + 接入维护 5%
```

不同功能单独评分，不存在一个模型在所有任务上永远最优。

## 10. 面试时怎么讲

可以这样表达：

> CareerOS 没有把所有 AI 请求直接绑定到单一模型。我先按任务将能力拆为文本结构化、视觉理解、语义检索和工具执行；MVP 使用低成本中文文本模型完成知识、JD 和笔记整理，通过 JSON Schema 校验、用户确认和调用日志保证可靠性。图片与向量检索在数据规模达到需求后再接入，并通过自建评测集比较质量、延迟、成本和稳定性。后端采用供应商适配层，因此更换模型不影响前端与业务 API。

这比“我接了一个大模型 API”更能体现产品和工程能力。

## 11. 当前结论

CareerOS 现在不是要找到“全市场唯一最强模型”，而是建立可替换架构并选出当前阶段的性价比组合：

1. 文本 MVP：优先实测 DeepSeek V4 Flash。
2. 图片：随后用真实截图对比 Qwen Vision 与 Gemini Flash。
3. Embedding：知识达到数百条或匹配质量不足时再加入。
4. 高质量备用：复杂简历/项目任务再考虑更强档模型。
5. 所有选择必须通过 CareerOS 自有测试集，而不是只看宣传和排行榜。
