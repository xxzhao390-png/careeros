# CareerOS 开发完成度与路线图

> 最后更新：2026-07-31  
> 当前目标：尽快完成一个可正常注册、保存数据、上传文件并具备基础 AI 能力的 MVP。  
> 维护规则：每完成一个功能，同步更新状态、完成比例、验证结果和更新时间。

## 1. 项目最终形态

CareerOS 不再额外建设“公开演示版”，只保留一套代码和两个相互隔离的部署环境：

| 环境 | 使用者 | 数据 | 访问方式 |
|---|---|---|---|
| 私人版本 | 项目所有者 | 保留当前真实求职数据 | 仅本人登录访问 |
| 公开版本 | 面试官及其他注册用户 | 每位新用户进入后都是空白工作台 | 公开网址注册使用 |

两个环境共用同一个 GitHub 代码仓库，但分别使用独立的 Cloudflare D1 数据库和 R2 文件存储。公开版本不会读取、复制或展示私人版本的数据。

```text
同一套 CareerOS 代码
├── 私人部署 → 私人 D1 + 私人 R2 → 保留真实数据
└── 公开部署 → 公开 D1 + 公开 R2 → 新用户空白数据
```

### 术语翻译

- `Deployment`：部署，把代码放到云端运行，得到可以访问的网址。
- `Environment`：环境，同一套代码对应的不同运行空间。
- `MVP`：最小可行产品，功能不求最多，但核心流程必须完整可用。
- `D1`：Cloudflare 提供的 SQL 云数据库，保存结构化数据。
- `R2`：Cloudflare 提供的文件存储，保存图片、PDF、Office 等文件。
- `Repository`：代码仓库，用于保存代码和修改历史。

# 第一阶段：MVP

## 4. MVP 产品目标

MVP 上线后必须满足：

1. 私人版本继续保留和使用当前真实数据。
2. 公开版本允许用户使用账号密码注册和登录。
3. 每个用户只能访问自己的岗位、任务、资料、知识卡和随手记。
4. 新注册用户看到空白工作台，不看到其他人的数据。
5. 数据刷新、退出或换设备后仍能读取。
6. 图片、PDF 和 Office 文件能够云端保存，并校验文件所有权。
7. 至少提供两个真实可用的 AI 工具。
8. 公开网址可以由面试官直接打开。
9. GitHub 包含源码、README、数据库说明和 API 文档。

后端逐步拆分为 `route → validation → service → repository → database`：

- `validation`：检查输入是否合法。
- `service`：执行业务规则。
- `repository`：负责数据库查询。
- `database`：D1 数据库。
