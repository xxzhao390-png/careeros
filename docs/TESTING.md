# CareerOS 测试说明

## 为什么分四层测试

| 测试层 | 主要视角 | 当前检查内容 |
|---|---|---|
| 单元与静态测试 | 开发者、代码视角 | 页面结构、API 路由、安全约束、AI 校验与限流 |
| API 集成测试 | 前后端协作视角 | 新增、查询、修改、删除与错误返回 |
| 权限隔离测试 | 安全、数据视角 | 用户 A 不能读取、修改或删除用户 B 的记录 |
| 浏览器端到端测试 | 最终用户视角 | 导航、新建随手记、自动保存、刷新保留、桌面端和移动端 |

四层不是重复劳动。单元测试定位代码错误最快；API 测试验证前后端约定；权限测试保护 D1 与 R2 中的用户数据；端到端测试验证用户真正点击时整条链路能够工作。

## 本地命令

```bash
npm run lint
npm run test:unit
npm run test:e2e
npm run test:all
```

本地端到端测试默认调用已安装的 Microsoft Edge。GitHub Actions 使用 Chromium，并在每次提交和 Pull Request 时自动执行构建、静态测试和端到端测试。

## 测试数据原则

- 自动化测试只使用本地开发环境和专用测试身份。
- API 权限测试使用两个不同测试用户，验证记录隔离。
- 每条自动创建的数据在断言完成后删除。
- 私人线上 D1、R2 只做只读核对；未经确认不创建、修改或删除真实数据。

## 当前覆盖与后续补充

当前 MVP 已覆盖核心数据链路。后续在文件上传功能接入公开环境后，补充 R2 上传、下载、越权访问和文件清理测试；接入模型后，再补充 AI 正常响应、超时、限流和异常格式测试。
